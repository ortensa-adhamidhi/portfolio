Hospitality · Power BI · Mews API + Primavera ERP

Wotels — Multi-Property Reporting

A star-schema Power BI platform unifying three data sources: live occupancy from the Mews API, finance actuals from Primavera ERP via SQL, and budgets from Excel. All flows into one governed, role-secured reporting environment across 18 properties and head office. The figures shown are synthetic; no real guest, revenue, or financial data.

01 / The Challenge

Three systems, no single source of truth

Wotels runs 18 properties plus a head-office overhead structure, but each side of the business lived in a different system. Live occupancy sat in their Mews PMS, actual financial results sat in Primavera ERP, and budgets sat in Excel. There was no single place to see Actual vs. Budget vs. Last Year across a property, a department, or the whole portfolio.

Every month-end close meant reconciling exports from three systems by hand, with no automated variance or drill-down.

02 / Approach

One star-schema model, three source systems

I built a star-schema Power BI model that pulls all three sources together. Custom Power Query (M) functions call the Mews API directly for daily occupancy by property, a SQL Server connection pulls P&L actuals from Primavera, and the Excel-based budget feeds the same fact table on a shared Date, Cost Center, and Unit grain.

DAX measures on top handle variance, YTD, and prior-year comparisons, and row-level security means each property manager and department head sees only their own numbers.

04 / Result

One governed model instead of three systems

The result is a single governed Power BI environment: a portfolio KPI dashboard, monthly and variance views for Units and Overhead P&L, and two executive summaries, all sitting on one semantic model with row-level security by property and department. What used to be a manual, three-system month-end close now runs from one place.
